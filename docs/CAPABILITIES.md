## 2. Measured parallel capacity

| Experiment | Result |
|---|---|
| 32 workers, 6 models, fully concurrent, no throttle | wall **2.7 s**; sequential-equivalent 42.5 s → **×15.6 speedup**; 12/32 failed |
| Cause of failures (read from response body, not guessed) | `HTTP 429 rate_limit_error: "Too many concurrent requests. Maximum 20 allowed per user."` |
| Is the cap per model or per user? | **Per user, across all models and both proxies** (8×4 models → 429s on every model; 16×2 → 10 of 16 Claude calls 429) |
| 60 tasks through `asyncio.Semaphore(18)` + exponential backoff | **60/60 HTTP 200, 0 retries, wall 12.1 s** |
| 6 sequential-burst Claude calls | 6×200 — bursts below the cap are fine |

### 2.1 Operating rule derived from the measurements

```
MAX_CONCURRENT_LLM_CALLS = 18        # hard platform cap is 20 per user; keep a margin
retry on 429: sleep 0.5·2^attempt, max 4 attempts
```

Any fan-out orchestrator (sub-agents, eval runners, batch extraction) **must** share one semaphore so the whole process never exceeds 18 in-flight requests. With that rule, throughput is ≈ 5 completed short calls/second sustained.

## 3. What this enables for Basira (today)

| Use | Pattern | Models |
|---|---|---|
| **Parallel sub-agents** for independent work packages (providers / pipeline / API / tests / eval / frontend / docs) | one orchestrator → N workers (≤18 in flight), each with a scoped prompt + file list, results reviewed before commit | Claude Opus/Sonnet for code, GPT-5.x as independent reviewer |
| **Cross-model review** (anti-hallucination) | same artefact judged by 2–3 different families; disagreements escalate to the engineer | Claude + GPT-5.2 + DeepSeek |
| **Eval generation** (150 cases, 500 false-alarm segments) | batch prompts, deterministic seeds, outputs validated against the corpus | Haiku-4-5 / gpt-5-mini (cheap, fast) |
| **LLM extraction provider** (competition day) | `providers/openai_compatible.py` against `$OPENAI_BASE_URL`; schema-enforced JSON; rules-only fallback | configurable; default `gpt-5-mini` or `claude-haiku-4-5` |

## 4. Boundaries that remain true regardless of model access
- Religious text is **never** generated by any model (red line 1). Models only locate spans or review code/docs.
- Every model output used in the repo is **verified** (tests, lint, corpus lookup, or a second model + human-readable diff) before commit.
- Sub-agent prompts and transcripts are not committed; only their verified artefacts are.
