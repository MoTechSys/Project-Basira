# ADR-0002: المطابقة الحتمية

## السياق
في مجال النصوص الشرعية، أي مطابقة "تقريبية" أو احتمالية تحمل مخاطر:
- قبول نص محرّف لأنه "قريب كفاية".
- عدم تكرار النتيجة لنفس المدخل = عدم إمكانية التحقق.
- تضليل المستخدم بـ"ثقة" رقمية (score 0.87) لا يفهمها.

## القرار
المطابقة النهائية **حتمية 100%**:
- تطبيع متفق عليه (normalization) محدّد التفاصيل.
- مقارنة حرف بحرف بعد التطبيع.
- نتيجة ثابتة لنفس المدخل في أي وقت وأي بيئة.
- الاسترجاع (retrieval) قد يكون تقريبياً، لكنه يختار **مرشحين فقط**.
  القرار النهائي يأتي من المطابقة الحتمية على كل مرشح.

## البدائل المرفوضة
- **vector similarity (cosine)**: مناسب للاسترجاع، لكن ليس للقرار النهائي.
- **fuzzy matching فقط**: يعطي نتائج متذبذبة.
- **ML classifier**: صندوق أسود لا يصلح لنصوص دينية.

## النتائج
- اختبارات حتمية (نفس المدخل = نفس المخرج دائماً).
- SHA للـ build + SHA للـ corpus = قابلية إعادة الإنتاج الكاملة.
- عند تعذّر المطابقة الحتمية → `needs_review` وليس "accept".
