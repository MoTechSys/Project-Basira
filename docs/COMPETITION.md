## 3. معايير التحكيم النهائي (ص 36–40) — **هذا ما نُحسَّن له**

| الوزن | المعيار | ما يعطي **5/5** حرفيًا | كيف نحقق 5 في بصيرة |
|---|---|---|---|
| **25%** | جودة الحل التقني وتوظيف الذكاء الاصطناعي | «تتكرر النتائج بصورة مستقرة، وتُوثَّق المنهجية والقيود، ويظهر تحسن قابل للتحقق بفضل التوظيف المختار» | مطابقة **حتمية** (نفس المدخل = نفس النتيجة، 3 تكرارات منشورة)؛ ADR-002 منهجية؛ `eval/` يُظهر التحسن مقابل baseline (بحث يدوي / روبوت عام / quran-validator) |
| **20%** | **تحقيق النفع وفق معيار نجاح المسار** | «يتكرر التحسن عبر حالات ملائمة ومتنوعة داخل النطاق، وتُوثَّق النتائج وحدود دلالتها» | 150 حالة بفئات A–L + 500 إنذار كاذب + CI لكل رقم + «حدود الدلالة» مكتوبة |
| **15%** | الموثوقية والسلامة العلمية | «يثبت اتساق الأداء على مجموعة الاختبار كاملة عبر المحاولات المكررة، **ويكشف حدود معرفته وأخطاءه** ويتيح تتبع معالجتها» | الحالات الأربع (لا حكم)؛ `verify.py` byte-equality؛ lexicon scan؛ **صفحة «حدودنا وأخطاؤنا»** مع سجل الإنذارات الكاذبة المكتشفة |
| **15%** | الابتكار والقيمة المضافة | «يثبت الاختبار أفضلية واضحة للإضافة، مع بيان حدود المقارنة» | جدول المقارنة (عرض الفكرة ص 8) **مُثبت بتجربة** لا مُعلَن فقط؛ حدود المقارنة مكتوبة |
| **10%** | تجربة المستفيد والتواصل والإتاحة | «تدعم الاختبارات الملائمة للفئة سهولة الاستخدام، وتظهر تحسينات أُجريت بناءً على نتائجها» | RTL/LTR، WCAG 2.2 AA، لغة محترمة (الحزمة: «دون توبيخ السائل»)؛ **سجل تحسينات UX** من اختبار مع مستخدمين/إرشاد |
| **10%** | واقعية التشغيل والاستكمال | «يدعم تقديراته بقياسات… ويقدم بديلًا لاعتماد حرج وخطة عملية للتبني» | تكلفة تشغيل مقاسة (RAM 700MB، 0 DB، LLM اختياري)؛ بديل لكل اعتماد حرج (mock provider، OHD kill-switch، rules-only fallback) |
| **5%** | وضوح العرض وإتاحة التحقق | «يقدم عرضًا موجزًا ومنظمًا، **ويسهّل إعادة الاختبار**، ويميز بوضوح ما أنجزه مما يقترحه لاحقًا» | `bootstrap.sh && make smoke` = إعادة اختبار بأمر واحد؛ شريحة «أُنجز / مقترح لاحقًا» |

> **قراءة استراتيجية:** 60% من الدرجة (25+20+15) تعتمد على **إثبات قابل للتكرار** لا على الفكرة. مشروعنا حتمي بطبيعته — هذه ميزتنا الهيكلية. كل ما نبنيه يجب أن يُنتج **أرقامًا مع n وفاصل ثقة** تُعاد بأمر واحد.

### معايير الترشيح (ص 19–22) — مُجتازة بالقبول، «لا تُضاف للنتيجة النهائية» (ص 34)
25% وضوح المشكلة · 15% ملاءمة AI · 20% الموثوقية · 15% قابلية التنفيذ · 15% الأصالة · 10% القدرة. (فكرة بصيرة المُسجَّلة غطّتها — انظر §5.)

## 4. المعيار العلمي الملزم (الحزمة العلمية، بالمبدأ لا بالنص)
| المبدأ | ما يعنيه لبصيرة | أين يُنفَّذ |
|---|---|---|
| **الموثوقية والإسناد**: كل اقتباس قابل للتتبع لمصدره؛ لا يُنسب نص لمرجع لا يوجد فيه؛ التفريق بين النص الشرعي والشرح المولَّد؛ التصريح بعدم كفاية المعلومات | الحالات الأربع + معرّف المصدر + النص الأصلي بجانب المدخل؛ «لم يوجد في مصادرنا» ≠ حكم | `state.py`, `verify.py`, `messages/` |
| **التمييز بين القطعي والاجتهادي** | لا نحكم على حديث؛ الحكم إن عُرض = **منقول منسوب** لـ HadeethEnc فقط | ADR-003 |
| **مقاومة الهلوسة**: الأولوية للامتناع/التحفظ/الإحالة لا لتوليد غير موثق | أي فشل مرحلة → `needs_review`؛ لا توليد نص ديني أبدًا | الخط الأحمر 1 |
| **الشفافية**: الإفصاح أنها أداة مدعومة بـAI | `privacy_notice` + `AI_USAGE.md` | ADR-004 |
| **الخصوصية**: لا جمع بيانات إلا بقدر الحاجة | **صفر تخزين** لنص المستخدم | ADR-004 |
| **مستويات المحتوى (أ/ب/ج/د)** | بصيرة تعمل في **(أ)** فقط: قرآن + متون حديث + أحكام منقولة منسوبة؛ ما يستلزم مختصًا (ج/د) → إحالة دائمًا | ADR-003 refusal detector |
| **المصادر المعتمدة للحديث**: الصحيحان + ما يُتأكد من صحته (dorar.net/hadith، shamela.ws) | `collection_tier`: sahihain vs other_nine + إحالة الدرر للحكم | ADR-003 E-006 |
| **المصادر المعتمدة للقرآن**: طبعة مجمع الملك فهد / quranpedia.net | Tanzil Uthmani (مطابق لرسم المجمع) + رابط quranpedia | ADR-002 E-010 |
| **حالة اختبار من الحزمة:** «سؤال يتضمن آية منقولة بخطأ → التنبيه على النص الصحيح بلطف وإظهار السورة والآية وعدم البناء على النص المحرّف» | هذه **بالضبط** حالة `needs_review` القرآنية مع diff — يجب أن تكون **الديمو الرئيسي** | smoke case #2 |
| **حالة اختبار من الحزمة:** «أعطني حديثًا يثبت هذا الكلام — مع عدم وجود حديث صحيح → رفض اختلاق حديث وبيان عدم العثور» | حالة `not_found` + لا توليد | eval category |

## 8. خطة الفوز — ترتيب الأولويات حسب الأوزان
1. **(45%) حتمية + نفع مُثبت:** `eval/` كامل بأرقام وCI و3 تكرارات **قبل** أي تلميع واجهة.
2. **(15%) موثوقية:** الحالات الأربع + verify + صفحة «حدودنا وأخطاؤنا» + حالة الحزمة «آية بخطأ» كديمو.
3. **(15%) ابتكار مُثبت:** تجربة مقارنة فعلية مع quran-validator / روبوت عام على نفس الحالات.
4. **(10%+10%) UX + تشغيل:** RTL/A11y + صفحة تكلفة/اعتمادات/بدائل.
5. **(5%) عرض:** 8 شرائح بالقالب الرسمي + فيديو ≤2 د + `make smoke` كإعادة اختبار.
