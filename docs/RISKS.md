# سجل المخاطر — بصيرة

> كل مخاطرة لها احتمال × أثر، وخطة تخفيف. يُحدَّث باستمرار.

## P0 — تمنع الإطلاق

### R-001: قبول نص محرّف كـ"found"
- **الاحتمال:** متوسط
- **الأثر:** كارثي (دينياً)
- **التخفيف:**
  - مطابقة حتمية حرف بحرف بعد التطبيع
  - مدقّق لاحق مستقل يرفض أي اختلاف
  - اختبارات adversarial على 500+ حالة
  - أي شك → `needs_review` وليس `found`

### R-002: توليد النموذج لنص قرآني غير موجود في المصدر
- **الاحتمال:** مرتفع (طبيعة LLMs)
- **الأثر:** كارثي
- **التخفيف:**
  - LLM يستخرج فقط من نص المستخدم (JSON schema صارم)
  - أي نص مرجعي يُعرض = من المدوّنة بمعرّفه
  - Post-validator يرفض أي مخرج فيه نص غير موجود في المدوّنة

### R-003: ادعاء "صحة" حديث من الأداة
- **الاحتمال:** متوسط (ضغط المستخدمين)
- **الأثر:** كارثي
- **التخفيف:**
  - الواجهة لا تحوي كلمة "صحيح" أو "ضعيف" من إنتاجنا
  - حكم الحديث يُنقل حرفياً من مصدر مرخّص فقط
  - صياغة واضحة: "وُجد اللفظ" ≠ "النسبة صحيحة"

## P1 — خطر عالٍ

### R-004: تحميل مصادر معطوبة أو مُعدَّلة
- **التخفيف:** SHA-256 pinning + TLS strict + fallback آمن

### R-005: استخدام مفرط يُفلس المشروع
- **التخفيف:** rate limiting + حدود حجم + تخزين مؤقت للنتائج

### R-006: فشل عرض الفروق للمستخدم العربي
- **التخفيف:** RTL صارم + اختبار 7 أجهزة + مراجعة من مُعرِّف

## P2 — خطر متوسط

### R-007: اعتماد على مزوّد LLM واحد
- **التخفيف:** تجريد Provider interface + دعم 3 مزوّدين

### R-008: تغيّر مصادر البيانات مع الوقت
- **التخفيف:** snapshot محلي + تثبيت الإصدار في manifest

## P3 — خطر منخفض

### R-009: Lighthouse score < 90
- **التخفيف:** قياس في CI + تحسين الأصول
