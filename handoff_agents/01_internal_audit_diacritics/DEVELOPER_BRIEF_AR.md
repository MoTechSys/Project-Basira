# بريف البناء الجديد ابتداءً من 4 أكتوبر — داخلي

## التكليف والحدود

ابنِ منتج تحقق من **النقل ونسبة المصدر**، لا مرجع فتوى ولا آلة تصحيح/تضعيف. هذه المسوّدة للتعلم فقط؛ لا تذكر اسم مستودعها أو تقريرها في العرض أو الفيديو أو أي ملف للمحكّمين. استخدم المعرفة الهندسية لتصميم جديد. لا تنسخ التنفيذ ثم تعيد تأريخه كعمل أيام التحدي. إذا استُخدم أي أصل سابق فعليًا، أفصح عن فئته ونطاقه بحسب قواعد المنظم دون كشف المواد الداخلية أو الادعاء بأنه تطوير جديد.

قبل البناء اكتب traceability matrix: كل وعد في الفكرة، منفذ/مؤجل، دليل، اختبار، مسؤول، رابط. قلّل الادعاء بدل تعويض فجوة بالكلام. لا تنشئ أعمالًا مؤرخة4 أكتوبر قبل حلول التاريخ.

## ما ينقل من المنهج — لا نسخًا أعمى للكود

1. سجل مصادر مرخصة ثابت الإصدارات والبصمات؛ عرض حرفي منفصل عن فهرسة البحث.
2. فصل الاستخراج عن الاسترجاع عن التحقق عن واجهة المستخدم؛ LLM مساعد مواضع لا صاحب حكم.
3. استخراج/اقتراح→إعادة ربط بالنص الأصلي→قبول أو رفض؛ لا نص مرجعي من النموذج.
4. بحث حرفي أولًا، ثم استرجاع lexical/fuzzy للمرشحين فقط، لا تحويل التشابه إلى صحة.
5. قوالب ثابتة عربية/إنجليزية، إحالة صريحة، wording «لم نجده في مصادرنا».
6. snapshot محلي موثوق لتحسين الإقلاع، واختبارات deterministic مع build/data SHA.
7. إظهار diff مع النص الأصلي، واحترام RTL والأرقام/المراجع ووضوح حدود المصدر.

## إعادة التصميم الأساسية

لا تختزل كل شيء في status واحد. اقترح في ADR وعقد API:

- `text_match`: found / partial_match / needs_review / not_found.
- `attribution`: verified / mismatch / unverified / not_applicable.
- `reading`: supported / unsupported / ambiguous.
- `context`: not_assessed / fragment / context_required.
- `coverage`: complete / truncated / extraction_uncertain.
- `overall`: needs_review عند تعارض النسبة أو تعذر الدليل أو القراءة غير المدعومة، حتى إن وجد اللفظ.
- `evidence[]`: مصدر/إصدار/معرف/موضع/نص حرفي/بصمة/مدى/سبب القبول وحدوده.

الأسماء قابلة للمراجعة، لكن لا يُسمح لواجهة خضراء أن تخفي تعارضًا. سياق المعنى لا يقيّمه LLM كفتوى؛ `not_assessed` حالة صريحة، مع إحالة ودليل حرفي عند الحاجة. لا تُظهر confidence رقميًا وكأنه يقين ديني؛ score للاسترجاع، غير probability of truth.

## الأولويات ومعايير القبول

### P0 — أول يوم، لا توسعة قبلها

| العمل | المعيار القابل للاختبار | مرجع العيب |
|---|---|---|
| مقارنة تحقق لا تمحو مادة دخيلة | HELLO/123 داخل اقتباس لا found؛ حذف التشكيل الغائب وحده لا يخلق إنذارًا |B02|
| فحص كل occurrence مستقلًا | تغيير ترتيب الصحيح/المخالف لا يغير الحكم الفردي؛ نسبة كل اقتباس محفوظة |B03|
| محاذاة تشكيل آمنة |16→review،17/18→found؛ تعذر المحاذاة ليس قبولًا |B01|
| validator مستقل من الطلب إلى المصدر | تعديل quote/span/keys/range/source/grade/version ينتج رفضًا آمنًا |B04|
| نسبة القول ونوعه |3/13/25/27 لا قبول شامل دون تحذير محدد؛ لا تخريج/حكم حديثي مولد |B05|
| مرجع كامل متعدد المواضع |الرحمن77 لا mismatch؛ الإخلاص1–999 مرفوض؛ مطابقة النطاق كاملًا |B06|
| اختبار أشد من code coverage |حالات حرجة + property/metamorphic + أزواج إيجابية/سلبية، CI يفشل على كل P0 |التقرير|

حجم عمل تقريبي P0: 14–22 ساعة عمل هندسية مركزة، قابل للتوازي بين backend/QA؛ لا يعادل ساعات تقويمية مضمونة لمطور منفرد. إذا تعذر ضمان النسبة/القراءة ضمن الوقت، اعرضها unverified وارفع overall للمراجعة بدل اختراع فحص ضعيف.

### P1 — استكمال اليومين الثاني والثالث

- تقسيم متون/أسانيد/مصادر ومقدمات الحديث القدسي؛ معالجة المركب غير المتصل؛ سياق الآية التالية عند الحاجة دون تفسير مولد.
- `source_segments[]` لكل الآيات لا مصدر أول فقط؛ اختبار DOM لقوالب grade وربط كل grade بسجله الحالي؛ عدم إرفاقه باقتباس مختلف.
- لا اقتطاع صامت عند30 quote/5000char؛ إظهار coverage وطلب التجزئة.
- OCR حقيقي إن بقي ضمن الوعد: فحص bytes/pixels، موافقة واضحة، صورة أصلية+نص مقروء، مراجعة يدوية قبل التأكيد، منع «تصحيح» OCR للنص المختلف. قس CER على صور واضحة/مزخرفة/تشكيل/ضغط؛ لا تسم mock OCR.
- LLM extractor اختياري مع timeout وbudget وfallback ومقارنة rules-only/LLM-only/combined على split ثابت. لا يُستخدم لاختيار حكم أو توليد نص مصدر.
- المتجهات إن ثبت أنها تحسن recall: retrieval only، exact proof يظل إلزاميًا؛ لا تؤخر P0 لأجلها. وإلا صرّح أنها غير مستخدمة بدل علم إعداد لا يعمل.
- XFF مع proxy موثوق، سقف limiter فعلي، size قبل القراءة/الإرسال، logs بلا نصوص شخصية، snapshot موثوق وغير قابل للكتابة في الإنتاج.
- Python lock، CI backend/frontend lint/type/test/E2E/security، build SHA حقيقي، README واحد يمكن لمراجع جديد اتباعه.
- أزرار الوصول/keyboard/focus، contrast يدوي، RTL/LTR، screen reader. axe0 ليس شهادة.

### P2 — دليل قيمة للفوز، لا مزايا للزينة

- اختبر مهمة واقعية مع5–8 مستفيدين مناسبين بعد موافقتهم وببيانات اصطناعية: زمن إيجاد المصدر، قرار النشر/المراجعة، نسبة فهم معنى «وُجد»، وأخطاء الثقة الزائدة.
- baseline محدد: بحث يدوي في مصدر/أداة محددة أو rules-only؛ نفس المدخلات والظروف، paired results وحدود العينة.
- بطاقة evidence قابلة للتصدير تبين ما تحقق وما لم يتحقق؛ لا شهادة صحة حديث.
- لوحة تشغيل بلا بيانات مستفيد: p50/p95، failures/timeouts، مزود fallback، cost per100 checks، current/peak RSS، uptime.

## بوابة الإنجاز للوكيل

لا تقل «اكتمل» حتى تتوفر: سجل P0/P1 مغلق باختبارات، نتائج raw قابلة للتكرار، مصدر حق واضح، README صحيح، رابط منتج فعلي، repo تسليم عام نظيف، LICENSE وسجل مصادر/أدوات/نماذج، limits وprivacy، عرض وفيديو وروابط تقديم. كل بند غير مكتمل يُعلّم صراحة، لا placeholder يبدو نهائيًا. تقدير87/100 في التقرير مشروط بهذه الأدلة ولا يضمن ترتيبًا.
